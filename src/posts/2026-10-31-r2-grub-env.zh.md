# 2026.10.31-r2：GRUB 启动不再报 sparse file not allowed

这是一个修复轮，不是新功能版。它只处理一个反复出现的问题：安装完成后首次启动，GRUB 在菜单前报 `commands/loadenv.c:check_blocklists:289:sparse file not allowed`，按任意键仍能进入系统。

## 版本信息

- 文件：`linxira-2026.10.31-r2-x86_64.iso`
- 大小：**5.35 GB**（5,352,212,480 字节）
- SHA-256：`e638c14713d0a105e7e261426e6a834abc31635fce4a010d015a35f016605c2b`
- 类型：测试镜像，不是正式版

## 根因不是“文件属性没设对”

上一版尝试在 btrfs 的 `/boot/grub` 上关 CoW（`chattr +C`），希望 `grubenv` 变成普通块。但 `grub-fstest blocklist` 在 btrfs 上仍然返回空 blocklist，GRUB 的 `load_env` 依旧判定为 sparse；同一个 1024 字节文件放到 FAT/ESP 上 blocklist 为 `2055+2`，连续可读。

还有一个更隐蔽的循环：`grub-mkconfig` 在 DB 默认值为 `saved` 时会执行 `grub-editenv - list`，而 `grub-editenv` 在文件不存在时会**主动创建一个空的 1024 字节 btrfs grubenv**。所以只在 `bootloader` 后删一次文件不够——后面任何一次 `grub-mkconfig`（包括 Timeshift 快照脚本）都会把它建回来。

## r2 的做法

1. UEFI 安装把 `grubenv` 放到 ESP：`EFI/linxira/grubenv`，并在 `/etc/grub.d/02_linxira-env` 用 `load_env -f` 加载、把 `env_block` 指回 ESP。
2. 目标机 `/etc/default/grub` 使用 `GRUB_DEFAULT=0`，不再用 `saved`；`GRUB_SAVEDEFAULT=true` 仍让菜单项写 `savedefault`，但 `grub-mkconfig` 不再调用 `grub-editenv - list`，从源头不创建 btrfs env。
3. 清理脚本移到所有 `grub-mkconfig` 之后；`linxiravalidate` 再做最后一次删除和校验。若 ESP env 缺失、没有 `saved_entry`，或 btrfs `/boot/grub/grubenv` 仍存在，安装直接失败，不生成首启报错的系统。
4. BIOS 安装没有 ESP：不创建 btrfs env，同时关闭 savedefault。代价是不记忆上次选择，但不会重复 sparse 报错。

## 边界

- 这是测试镜像；r2 已完成构建、静态检查与 CI，但**尚未做真实 UEFI 启动验证**。
- 「上次选择」依赖 GRUB 的 `save_env -f` 写 ESP；需要在实机上选择一次 Windows/Linux，再重启确认。
- 若仍出现报错，请提供 `cat /etc/linxira-release`、`findmnt /boot/efi`、`grub-editenv /boot/efi/EFI/linxira/grubenv list` 和 `ls -l /boot/grub/grubenv` 的输出。
