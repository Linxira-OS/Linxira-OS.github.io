# 2026.10.31-r2: GRUB no longer reports sparse file not allowed

This is a fix round, not a feature release. It addresses one recurring failure: after installation, the first boot shows `commands/loadenv.c:check_blocklists:289:sparse file not allowed` before the menu. Pressing any key still boots, but the system carries the problem forward.

## Build

- File: `linxira-2026.10.31-r2-x86_64.iso`
- Size: **5.35 GB** (5,352,212,480 bytes)
- SHA-256: `e638c14713d0a105e7e261426e6a834abc31635fce4a010d015a35f016605c2b`
- Type: test image, not a stable release

## The root cause was not a missing file attribute

The previous build set `chattr +C` on btrfs `/boot/grub`, expecting `grubenv` to become a normal extent. `grub-fstest blocklist` still returned an empty blocklist on btrfs, so GRUB's `load_env` kept treating it as sparse. The same 1024-byte file on FAT/ESP returns blocklist `2055+2` and reads as contiguous.

There was a second loop: when the default is `saved`, `grub-mkconfig` runs `grub-editenv - list`, and `grub-editenv` **creates an empty 1024-byte btrfs grubenv when the file does not exist**. Deleting the file once after `bootloader` was not enough; any later `grub-mkconfig` (including the Timeshift snapshot script) recreated it.

## What r2 changes

1. UEFI installs place `grubenv` on the ESP at `EFI/linxira/grubenv`; `/etc/grub.d/02_linxira-env` loads it with `load_env -f` and points `env_block` back at the ESP.
2. The target `/etc/default/grub` uses `GRUB_DEFAULT=0` instead of `saved`. `GRUB_SAVEDEFAULT=true` still writes `savedefault` from menu entries, but `grub-mkconfig` no longer calls `grub-editenv - list`, so it never creates a btrfs env.
3. Cleanup now runs after every `grub-mkconfig`; `linxiravalidate` performs one final removal and check. A missing ESP env, a missing `saved_entry`, or a leftover btrfs `/boot/grub/grubenv` fails the install rather than producing a system that errors on first boot.
4. BIOS installs have no ESP: no btrfs env is created and savedefault is disabled. The tradeoff is no last-selection memory, but the sparse failure cannot recur.

## Boundaries

- This is a test image. r2 passed build, static checks, and CI, but **no real UEFI boot test has been run yet**.
- Last-selection depends on GRUB `save_env -f` writing to the ESP; select Windows/Linux once, reboot, and confirm.
- If the error still appears, provide `cat /etc/linxira-release`, `findmnt /boot/efi`, `grub-editenv /boot/efi/EFI/linxira/grubenv list`, and `ls -l /boot/grub/grubenv`.
