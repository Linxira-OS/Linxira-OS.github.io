# 多底座路线预告：Arch、Ubuntu 与 NixOS 的边界

> 2026-11-08 · 公告

## 为什么现在说这件事

Linxira 的定位一直不是“再造一个发行版”，而是**在上游发行版之上提供一层可移除的快捷安装与治理层**。这层能力包括 catalog、事务计划/确认/回执、签名仓库、配置入口、更新提醒、崩溃监视与欢迎中心。

现在我们准备把这层能力铺到更多底座上。原因很直接：开发主力机、科学计算用户、国产 GPU 推理机、ARM 本地大模型机器，对底座的要求并不一样。与其让所有人挤在一个 Arch 上，不如把边界讲清楚。

## 三条线，三种承诺

| 线 | 底座 | 定位 | 更新节奏 | 退出方式 | 状态 |
|---|---|---|---|---|---|
| **Arch x86_64** | Arch Linux | 主力开发机，也可做推理机 | 滚动更新；计划每月发布一次 ISO 快照 | 卸掉 `linxira-*` 后回到原生 Arch，随时可退出 | 当前主线 |
| **Ubuntu x86_64 / ARM64** | Ubuntu 26.04 LTS | 推理机、科学计算、国产 GPU；ARM 侧面向 DGX Spark、N1X 等机型 | LTS 定点版本 + 上游安全更新；HWE 内核随点版本跟进 | 基于 Ubuntu 的衍生层，可移除，但**不是** Arch 那种“滚动退出” | 调研中 |
| **NixOS** | NixOS（VM / 容器） | 可复现的参考环境、benchmark、工具链 | flake 锁定，按需更新 | 只交付配置与 flake，不做发行版承诺 | 实验性，无 SLA |

## 关于 Ubuntu 2027：没有 2027 LTS

先把时间线说清楚，避免等待一个不存在的版本：

- Ubuntu 26.04 LTS：2026-04-23 发布，标准安全维护到 **2031-05**，ESM 到 2036。
- Ubuntu 26.10：2026-10 发布，仅 9 个月支持，**2027-07 结束**。
- Ubuntu 27.04 “Tenacious T-Rex”：**2027-04-22** 发布，仍是 9 个月 interim。
- Ubuntu 27.10：2027-10 发布，仍是 interim。
- 下一个 LTS 是 **28.04（2028-04）**。

所以不存在“等 2027 年 7 月之后发长期版”这回事。如果目标是 **LTS + 7.3 内核**，正确的时间点是 **26.04.2 点版本（2027-02-18）**：按 Ubuntu HWE 节奏，它会把 26.10 的 7.3 内核带进 26.04 LTS（最终以 Ubuntu release notes 为准）。不想等的话，只能先用 26.10 做过渡镜像，接受 9 个月生命周期。

## 中国网络环境：三条线的现实差异

这是我们必须提前讲清楚的约束：

- **Arch**：国内镜像最完整（TUNA、USTC、阿里云等），`linxira-config` 已经可以做镜像选择；计划中的月度 ISO 会放在 GitCode / 国内对象存储，不依赖境外下载。
- **Ubuntu**：官方归档有国内镜像（TUNA、USTC、阿里云、华为云等），apt 源和 ISO 都可以走国内；安装器会提供国内源选项。对绝大多数用户来说，Ubuntu 的安装难度并不比 Arch 高。
- **NixOS**：TUNA、USTC、SJTU 提供 nix-channels 与 binary cache 镜像，但覆盖面和稳定性并不保证。所以在镜像访问稳定之前，**NixOS 只做实验性 VM 参考环境，不做绝对承诺**，也不建议作为普通用户的主系统。
- **国产 GPU**：摩尔线程、昇腾等厂商的驱动与工具链主要以 Ubuntu 为载体；这是 Ubuntu 线存在的现实理由，不是偏好。
- **DGX Spark / N1X**：NVIDIA 官方 DGX OS 基于 Ubuntu 26.04 LTS ARM64，但镜像下载可能受账号/网络限制；这条线只对具体机型做白名单支持，不承诺通用 ARM。

## 我们坚持的边界

1. **薄层、可退出**：Arch 线卸掉所有 `linxira-*` 后仍是可用的原生 Arch；Ubuntu 线同样保持层可移除，但它不是滚动发行版，退出语义不同。
2. **只带常用软件**：不塞赞助商软件、不塞奇怪的系统级组件；catalog 里每个包都有来源、许可证、信任级别。
3. **供应链默认保守**：Arch 默认不启用 AUR；Ubuntu 默认不启用未审核 PPA；厂商 deb 先进入我们审核过的签名仓库；全线不推荐 `curl | sh`。
4. **不自建内核**：Arch 用官方最新内核；Ubuntu 用 HWE / 厂商内核；没有完整自动化流水线之前，不做 v3 / CachyOS 派生内核。
5. **AI 是可选能力**：默认不自动运行 agent；crash-watch 默认 0 token 分流，只有用户点击才启动分析，本地只读、不上传。

## 下一步

- **Ubuntu 线**：先调研 26.04 LTS + 7.3 HWE、国产 GPU 驱动、DGX Spark / N1X 白名单；在调研完成前不承诺发布日期。
- **NixOS**：只做 flake / VM 配置，作为可复现参考环境，不做发行版。
- **Arch 线**：继续现有主线，推进月度 ISO 快照与可退出性验收。

这条路线不追求“支持一切”，而是把每条线的承诺写清楚：**Arch 负责滚动的自由，Ubuntu 负责推理与厂商硬件，NixOS 负责可复现。**
