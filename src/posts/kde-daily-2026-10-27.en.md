# 2026.10.27 (r4): KDE is ready for daily use

This release does not change the architecture and does not pile on features. It does one thing: fix the parts of the KDE desktop that kept getting in the way, so the machine can go from test install to the computer you boot every morning. This post covers what changed, where the boundaries are, and why we still do not call it a stable release.

Verify the checksum before writing the image. The size is in the same range as the previous build: offline software set plus dual kernels.

## What this release fixes

All three are the kind of problem that does not block installation but shows up every day:

**Terminal dispatch no longer crashes.** Clicking "open terminal" from the application menu, the update tray or the crash watcher used to exit immediately under COSMIC — `cosmic-term` does not accept `-e`. There is now a single dispatch chain: `konsole` first, then `alacritty`, then `xterm`; if none is present, a temporary `Terminal=true` desktop entry is generated and handed to `gtk-launch`, then cleaned up after five seconds. `alacritty` runs with `--hold`, so the window does not vanish when the command exits. The fixes ship in config-hub 2.6.2, linxira-update 0.1.10 and crash-watch 0.1.3.

**Updates heal a missing sync.** When the pacman database has no synced repository, the update check used to fail outright. It now runs a `pacman -Sy` under root with a 120-second timeout, then re-detects foreign packages; once the mirrors respond, the update continues instead of dropping you on an error page.

**COSMIC becomes a first-class desktop.** Its packages ship on the ISO, and the installer's software step offers four profiles: KDE Plasma, COSMIC, headless with the full toolset, and headless minimal. No post-install network round trip to add a desktop.

All of these also ship through the signed repository: existing systems get them with `sudo pacman -Syu`, no reinstall required.

## What "daily use" actually means

- Opening a terminal from the menu, the tray or the crash watcher works from every entry point, and the window stays open.
- A failed update check no longer means fixing sources by hand; it syncs first and only errors when that fails.
- A snapshot is taken before every update, and GRUB lets you boot back into it.
- Chinese installs get input method and locale configured out of the box.
- Bluetooth, Wi-Fi, printing and the display manager are Arch's own components; we do not swap them for a custom layer.

In other words, on the KDE path you no longer have to work around the system's own components to get through a day. That is the basis for "daily use" — not a benchmark score, and not the length of a feature list.

## We only maintain two desktops

Plasma and COSMIC are the two desktops we actually maintain and test, and the installer's four profiles are organized around them. GNOME, XFCE, Hyprland and the rest remain installable exactly as they are on Arch, but that falls under "Arch can install it, we do not adapt for it": we do not promise that login, terminal, updates and snapshots behave the same on other desktops.

We do plan **limited compatibility** for ultra-light desktops such as XFCE — the goal is "installs, basic functionality works, does not block updates", not promoting it to a third first-class desktop. There is no schedule; when it is done, the documentation will state exactly how far support goes.

## About the word "stable release"

Some will ask whether this counts as a stable release. Under the project's current release policy, a stable release needs a verifiable release manifest. This build does not have one, so it stays in the beta sequence, and the documentation and download page use that wording.

But "is it a stable release" and "can it be your daily machine" are different questions. On the KDE path, every scenario listed above works today; using it as your main system does not require waiting for a label.

## How to get it

- **Fresh install**: download the r4 image, verify the SHA-256, write it to a USB stick, and pick KDE Plasma or COSMIC in the installer's desktop step.
- **Existing system**: `sudo pacman -Syu`, then confirm config-hub ≥ 2.6.2, linxira-update ≥ 0.1.10 and crash-watch ≥ 0.1.3.
- **Only the fixes**: all three packages live in the signed `[linxira]` repository and can be upgraded on their own.

## Known issues

- RDP / VNC remain unavailable: xrdp is not in the signed repositories. Use SSH + X11 forwarding for remote desktop.
- Desktops other than Plasma and COSMIC are outside the maintenance scope; check upstream documentation first for desktop-specific problems.
- Systems upgraded from older images keep their existing sshd and pacman configuration; after upgrading, review `/etc/ssh/sshd_config.d/` and `/etc/pacman.conf`.

If you hit something not listed here, collect diagnostics with `linxira-config logs collect` and file a repository issue.
