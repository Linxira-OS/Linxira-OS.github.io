# 2026.10.27（r4）：KDE 桌面可以当主力了

这个版本没有换架构，也没有堆新功能。它只做了一件事：把 KDE 桌面上那些「用着用着就卡住」的环节逐个修掉，让这台机器可以从装机测试机变成每天开机干活的机器。本文说明改了什么、边界在哪，以及为什么我们仍然不把它称作稳定版。

## 版本信息

- 文件：`linxira-2026.10.27-r4-x86_64.iso`
- 大小：**5.34 GB**（5,336,342,528 字节）
- SHA-256：`9f62b11fa595051103dd24878a0fe81702010b6942ac3128eb64a81d2d93ce70`
- 下载：[官网下载页](/zh/download/)、GitCode `iso-release` 仓库

下载后先校验再写盘。镜像体积主要来自离线软件集与双内核，与上一版同一量级。

## 这个版本修了什么

三个问题都属于「不影响安装、但天天用就会遇到」的类型：

**终端派发不再闪退。** 之前从应用菜单、更新托盘或崩溃监视器里点「打开终端」，在 COSMIC 下会直接退出——`cosmic-term` 不认 `-e` 参数。现在统一走一条派发链：优先 `konsole`，其次 `alacritty`，再退到 `xterm`；三者都不在时，临时生成一个 `Terminal=true` 的桌面条目交给 `gtk-launch`，5 秒后自动清理。`alacritty` 使用 `--hold`，避免命令结束后窗口立刻消失。相关修复在 config-hub 2.6.2、linxira-update 0.1.10、crash-watch 0.1.3。

**更新能在缺源时自愈。** 如果 pacman 数据库里没有已同步的仓库，更新检查过去会直接失败。现在会先以 root 身份执行一次带超时的 `pacman -Sy`（120 秒上限），再重新检测外部包状态；源恢复正常后，更新流程继续，而不是把用户丢在报错页。

**COSMIC 正式成为第二个一等桌面。** 桌面包随镜像离线附带，安装器的软件选择步骤给出四个档位：KDE Plasma、COSMIC、无桌面（完整工具集）、无桌面（超精简）。不再需要装完系统再联网补桌面。

这些修复同时通过签名仓库下发，已经装好的系统 `sudo pacman -Syu` 就能拿到，不必重装。

## 「能当主力」具体指哪些场景

- 从菜单、托盘、崩溃监视器任何入口点「终端」，都能正常打开，不会一闪而过。
- 更新检查失败后不再需要手动修源；缺同步时它自己补，补不上才报错。
- 更新前自动快照，出问题能从 GRUB 选快照回滚。
- 中文安装环境下输入法、区域设置开箱即用。
- 蓝牙、Wi-Fi、打印、显示管理器使用 Arch 官方组件，没有自研替换层。

换句话说，KDE 这条线上已经不需要「绕开系统自带的东西」才能完成日常工作。这是我们说「可以当主力」的依据，不是跑分，也不是功能清单的长度。

## 我们只维护两个桌面

Plasma 与 COSMIC 是我们实际维护、实际测试的两个桌面，安装器里的四个档位也都围绕它们组织。GNOME、XFCE、Hyprland 等其它环境仍然可以像在 Arch 上一样自行安装，但那属于「Arch 能装，我们不为它做适配」的范围：不保证登录、终端、更新、快照这些系统集成在别的桌面上表现一致。

后续计划对 XFCE 这类超轻量桌面做**一定程度的兼容**——目标是「装得上、基础功能可用、不挡更新」，而不是把它提升为第三个一等桌面。这项工作没有时间表，做完了会在文档里写明支持到什么程度。

## 关于「正式版」

有人会问这个版本算不算正式版。按项目当前的发布规范，正式版需要可校验的 release manifest；这一版没有，所以我们仍然把它放在测试版序列里，文档和下载页也按这个口径写。

但「是不是正式版」和「能不能日常用」是两件事。就 KDE 桌面而言，本文列出的场景都已经打通；把它当主力机使用，不需要等一个标签。

## 怎么拿到这个版本

- **新装**：下载 r4 镜像，校验 SHA-256 后写盘，安装时在「桌面环境」选择 KDE Plasma 或 COSMIC。
- **已有系统**：`sudo pacman -Syu`，确认 config-hub ≥ 2.6.2、linxira-update ≥ 0.1.10、crash-watch ≥ 0.1.3。
- **只想用更新修复**：三个包都在 `[linxira]` 签名仓库里，单独升级也可以。

## 已知问题

- RDP / VNC 仍不可用：xrdp 没有进入签名仓库，远程桌面请用 SSH + X11 转发。
- 非 Plasma / COSMIC 桌面不在维护范围，遇到桌面相关问题请先对照上游文档。
- 从旧镜像升级上来的系统，如果之前手动改过 sshd 或 pacman 配置，升级不会覆盖这些文件；升级后建议核对 `/etc/ssh/sshd_config.d/` 与 `/etc/pacman.conf`。

如果在这个版本上遇到上面没列的问题，用 `linxira-config logs collect` 收集诊断，再通过仓库 issue 反馈。
